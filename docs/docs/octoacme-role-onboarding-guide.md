# OctoAcme Role Onboarding Guide

## Welcome to the Project!

New team member? Use this guide to quickly understand your role, who you'll work with, and key artifacts.

---

## For Developers

### Day 1
- Read `octoacme-project-management-overview.md`
- Clone repo, set up dev environment
- Attend daily standup (observe or participate if ready)

### Week 1
- Complete code review on 1-2 PRs
- Attend sprint planning and estimate a backlog item
- Meet Product Manager and Project Manager
- Read `octoacme-execution-and-tracking.md`

### Week 2+
- Pick up first story and submit PR with comments
- Participate in design review (if applicable)
- Attend sprint review and retrospective
- Check in with Scrum Master on any blockers

### Key Contacts
- **Scrum Master**: Day-to-day support, impediment removal
- **UX Designer**: Design questions, implementation approach
- **Security Champion**: Code review from security perspective
- **Project Manager**: Timeline, scope, external dependencies

---

## For Product Managers

### Day 1
- Review `octoacme-project-management-overview.md` and `octoacme-project-initiation.md`
- Understand the Product Charter and current roadmap
- Meet the Project Manager, Development Lead, and key Stakeholders

### Week 1
- Attend sprint planning and backlog refinement
- Refine top 3 backlog items: write clear acceptance criteria
- Sit in on 1 design review and 1 sprint review
- Define success metrics for your area

### Week 2+
- Own weekly PM/Project Manager sync
- Gather customer feedback from Customer Support
- Review sprint metrics and velocity
- Present weekly status to Stakeholders

### Key Contacts
- **Project Manager**: Coordination, schedule alignment
- **Developers**: Technical feasibility, trade-offs
- **UX Designer**: Design vision and user experience
- **Customer Support**: Market feedback and user needs
- **Business Analyst**: Requirement clarity

---

## For Project Managers

### Day 1
- Read all `octoacme-*.md` docs (especially overview, initiation, planning, execution)
- Understand current project status, risks, and blockers
- Meet all core roles: PM, PdM, Dev Lead, Scrum Master

### Week 1
- Set up project board, risk register, status report template
- Host or attend sprint planning
- Identify top 3 blockers and escalation paths
- Schedule recurring meetings (daily standup, weekly sync, weekly status)

### Week 2+
- Facilitate retrospectives and track action items
- Maintain risk register (review at weekly PM sync)
- Provide weekly status to Stakeholders
- Escalate blockers per the escalation matrix

### Key Contacts
- **Product Manager**: Weekly alignment, roadmap
- **Scrum Master**: Process coaching, team health
- **Developers**: Progress, blockers, technical risks
- **Security Champion**: Security risks and review timelines
- **Stakeholders**: Status updates and decisions

---

## For UX Designers

### Day 1
- Read `octoacme-project-management-overview.md`
- Review product vision and user research
- Attend sprint planning or daily standup (observer)

### Week 1
- Meet Developers, Product Manager, and Customer Support
- Understand current user flows and pain points
- Participate in design review with Product Manager
- Read `octoacme-project-planning.md` for how design fits into sprints

### Week 2+
- Conduct design critique or user testing session
- Provide design specs to Developers before sprint start
- Attend sprint review for feedback
- Gather feedback from Customer Support on usability

### Key Contacts
- **Product Manager**: Vision, user research, priorities
- **Developers**: Technical feasibility, implementation questions
- **Customer Support**: User pain points and feedback
- **Business Analyst**: Business rules and edge cases

---

## For Business Analysts

### Day 1
- Read `octoacme-project-management-overview.md` and `octoacme-project-planning.md`
- Understand current scope, requirements, and key dependencies
- Meet Product Manager and Project Manager

### Week 1
- Attend sprint planning or backlog refinement
- Conduct interviews with 2-3 Stakeholders to understand requirements
- Document current business workflows
- Create requirement specification template

### Week 2+
- Facilitate requirement workshops
- Provide clarifications to Developers during sprint
- Validate acceptance criteria with Stakeholders
- Help plan UAT with Customer Support

### Key Contacts
- **Product Manager**: Product vision and user needs
- **Project Manager**: Scope, timeline, dependencies
- **Developers**: Technical feasibility and edge cases
- **Stakeholders**: Requirements and validation

---

## For Security Champions

### Day 1
- Read `octoacme-project-management-overview.md`
- Review security requirements and threat model (if exists)
- Meet Project Manager and Development Lead

### Week 1
- Attend sprint planning (security requirements discussion)
- Review current architecture and security posture
- Set up security review process for PRs and designs
- Schedule 1-on-1 with key developers

### Week 2+
- Participate in design reviews (security perspective)
- Review PRs and provide security feedback
- Track security risks in risk register
- Escalate vulnerabilities to Project Manager

### Key Contacts
- **Project Manager**: Risk escalation, timeline coordination
- **Developers**: Code review, security guidance
- **UX Designer**: Secure authentication, data handling
- **Product Manager**: Security as feature

---

## For Customer Support Representatives

### Day 1
- Read `octoacme-project-management-overview.md`
- Review current product and known support pain points
- Meet Product Manager and Project Manager

### Week 1
- Attend sprint planning or demo (understand new features)
- Interview 3-5 customers about pain points
- Summarize feedback trends for Product Manager
- Plan how to support new features post-release

### Week 2+
- Provide weekly feedback summary to Product Manager
- Participate in design reviews or UAT
- Train internal team on new features
- Escalate critical customer issues to Project Manager

### Key Contacts
- **Product Manager**: Feature prioritization, customer feedback
- **Project Manager**: Customer-impacting issues, timelines
- **UX Designer**: Usability feedback
- **Developers**: Critical bug escalation

---

## For Scrum Masters

### Day 1
- Read `octoacme-project-management-overview.md` and all execution/retrospective docs
- Meet Project Manager, Product Manager, and Development Team
- Understand current sprint cadence and ceremonies

### Week 1
- Facilitate daily standup (observe first day, then run)
- Attend sprint planning and retrospective
- Identify 3 process improvements to discuss
- Meet 1-on-1 with each developer

### Week 2+
- Run all ceremonies (standup, planning, review, retrospective)
- Track and escalate impediments to Project Manager
- Mentor Product Manager on backlog refinement
- Track team velocity and retrospective action items

### Key Contacts
- **Project Manager**: Blocker escalation, timeline coordination
- **Product Manager**: Backlog refinement coaching
- **Developers**: Impediment removal, process coaching
- **All Team**: Psychological safety and continuous improvement

---

## General Tips

✅ **Do**:
- Read the docs for your role in the first week
- Ask questions! Team is here to help.
- Attend ceremonies to build relationships
- Check in with your role-specific lead by day 3

❌ **Don't**:
- Skip onboarding conversations—they matter
- Assume you know the process without reading docs
- Make decisions in isolation—ask your team first
- Forget to document what you learn for future teammates

---

## Questions?

- **Process question**: Ask your Project Manager or Scrum Master
- **Product question**: Ask your Product Manager
- **Technical question**: Ask the Development Lead
- **UX/Design question**: Ask the UX Designer
- **Requirement question**: Ask the Business Analyst
- **Security question**: Ask the Security Champion
